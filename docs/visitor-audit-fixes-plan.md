## Edge cases (most → least critical) — each followed 3 levels down
| # | Edge case (L1 → L2 → L3) | Solution |
|---|---|---|
| E1 | Upgrade passes local tests → but behaves differently on Cloudflare Workers → visitors see broken pages after deploy. | We build with the real Cloudflare builder before merging, then check the first live build and pages right after. If anything breaks, Cloudflare can switch back to the previous version in one click. |
| E2 | Database goes down → all 9 page parts fail at once → problem reports pile up and can't be saved either. | Each part reports at most once per hour per server copy, and reporting never crashes the page. Reports that can't be saved wait in a retry line that has a daily limit, so it can't overflow (a later email clean-up must keep that retry line). |
| E2b | Database is down → the problem write also hangs → pages would load slowly while waiting to log the error. | The report is handed off to run after the page is sent, so the visitor never waits for it. The page shows its normal "missing piece" fallback right away. |
| E3 | Fixing PR #41's conflicts → accidentally undoes a newer change (like the removed dashboard card) → owner sees old features come back. | Every conflict has a written rule (keep the newer build1 version, add only #41's new lines). All tests must match the before-results exactly. |
| E4 | Database recovers, then fails again in the same hour → second outage is not reported → owner thinks it was short. | The first report of that hour already flags the problem. A new hour gives a new report, so long or repeating outages always show up. |
| E5 | Next 16.4 changes how page titles/tags load → share previews or tab titles change → links shared on Facebook look wrong. | We save the page header tags before and after the upgrade and compare them. Tests read the tags the way Facebook does. |
| E6 | Visitor sends a 3rd form in an hour → the email system skips their copy → a promise of "we sent a copy" would be false. | We remove that promise (or use wording that never promises), so what we say is always true. |
| E7 | Turnstile library update → changes its style text → the style is blocked again, or the widget looks off. | A test compares the library's style text to the allowed one. If they differ, the test fails before anything goes live. |
